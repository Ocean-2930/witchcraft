# Video to Motion Sheet

사용자가 제공한 영상에서 실제 동작을 추출한다. Hailuo 생성이나 API 키는 필요하지 않다. 스킬 이름의 `vedio_to_motion_sheet` 표기는 사용자가 지정한 이름이므로 유지한다. 텍스트 파일은 UTF-8로 읽고 쓴다.

## 고정 출력 규격

- 가로 1행 × 8열, 왼쪽부터 시간순으로 배열한 RGBA PNG.
- 모든 작업의 한 프레임은 **512×512px**, 전체 시트는 **4096×512px**로 통일한다. 영상 크기나 캐릭터 크기에 따라 프레임 규격을 바꾸지 않는다. 사용자가 명시적으로 다른 규격을 요청한 경우에만 변경한다.
- 0~6번은 한 주기를 대표하는 서로 다른 7개 시점, 7번은 최종 보정된 0번의 픽셀 단위 복제다. 총 8칸 안에 동일 시작·종료 자세를 포함한다.
- 반복 재생은 0~6번만 사용하고, 첫 자세로 종료할 때 7번을 표시한다. 8칸 전체를 반복하면 동일 자세가 경계에서 중복되어 잠깐 멈출 수 있음을 사용 설명에 기록한다.
- 배경과 빈 여백은 반드시 **alpha=0**. 검정/흰색 배경이나 RGB에 그린 체크무늬는 투명 배경으로 인정하지 않는다. 캐릭터 경계의 안티앨리어싱과 실제 반투명 표현은 유지하되, 빈 배경에 잔여 불투명 픽셀을 남기지 않는다.
- 머리카락·망토·무기·복원한 부분까지 포함한 전체 동작의 최대 범위를 기준으로 상하좌우 최소 **32px**의 투명 여백을 확보한다. 기본 유효 영역은 448×448px 이내이며 비율을 유지한다.
- **발 기준선은 각 512×512 프레임의 상단에서 y=448px**이다. 좌표 원점은 셀의 왼쪽 위 (0,0), y는 아래로 증가한다. 지면에 닿은 발바닥의 하단 경계를 이 선에 맞추므로 발 아래에는 기본 64px의 공간이 남는다. 두 발이 모두 닿으면 두 발의 접지면을 같은 기준선에 맞춘다.
- 발 기준선은 접지한 발에 적용한다. 들린 발을 강제로 내리지 않고, 점프나 공중 동작에서도 기준선은 가상의 지면으로 고정한다. 검끝·망토·그림자의 최하단을 발바닥으로 오인하지 않는다. 접지 순간을 기준으로 공통 배율과 기본 위치를 정하고 의도된 상하 움직임은 보존한다.
- 기존 시트의 발 기준선이 다르면 새 결과의 기본값은 y=448px로 유지하고 기존 시트와의 차이를 알린다. 사용자가 기존 시트에 맞추도록 명시한 경우에만 그 기준선을 따르고 실제 사용한 좌표를 결과에 기록한다.
- 같은 캐릭터의 다른 모션 시트가 있으면 그 시트의 캐릭터 크기와 기준점을 우선 맞춘다. 추가 여백이 필요한 동작은 클리핑하지 말고 크기 조정 필요성을 알린다.

## 처리 흐름

1. **입력 확인과 동작 분석**
   - `ffprobe`로 해상도, 길이, 프레임률과 타임스탬프를 확인한다.
   - FFmpeg로 저해상도 연락 시트와 필요한 원본 프레임을 추출해 직접 살펴본다. 임의로 영상의 첫 1초를 루프라고 가정하지 않는다.
   - 발·손·무기·머리카락의 반복 위상을 비교하여 자연스러운 한 주기를 고른다. 시작 직후의 정지나 마지막 감속 구간은 피한다.
   - 정확한 반복 구간이 없으면 원본으로 가능한 범위를 평가하고 한계를 알린다. 첫·끝을 복제한 사실만으로 중간 동작까지 매끄럽다고 판정하지 않는다.

2. **FFmpeg 분할**
   - 선택한 주기에서 종료 지점을 제외하고 7개의 시점을 균등하게 샘플링한다. 가변 프레임률 영상은 프레임 번호 대신 타임스탬프를 기준으로 처리한다.
   - 영상 프레임의 추출·자르기·리사이즈·배치에는 FFmpeg를 사용한다. 원본 영상은 보존한다.
   - 중간 검토용 연락 시트는 다른 배열이어도 되지만 최종 결과는 반드시 1×8이다.

3. **배경 제거 및 잘린 부분 복원**
   - 배경과 피사체 색이 확실히 분리될 때만 FFmpeg 크로마키를 사용한다. 검은 배경에 검은 갑옷·칼날이 있는 경우 전체 검정색을 일괄 제거하지 않는다.
   - 정교한 배경 추출이나 없는 부분의 복원이 필요하면 사용 가능한 `imagegen` 스킬을 읽고 내장 이미지 편집 도구를 사용한다. 편집할 로컬 이미지는 먼저 확인한다.
   - 프롬프트에는 원본의 서로 다른 포즈, 표정, 의상, 무기 각도, 프레임 순서를 보존하고 배경 및 손실 영역만 수정하도록 명시한다. 실제 알파 채널이 있는 PNG를 요청한다.
   - 잘린 칼끝·머리카락·망토·신체는 인접 프레임의 온전한 형태를 참고하여 복원한다. 모든 프레임에서 무기의 길이와 디자인을 일관되게 유지하고 복원 공간을 먼저 확보한다.
   - 보이지 않는 영역은 추정 복원임을 결과에 밝힌다. 복원이 불가능하거나 결과가 부자연스러우면 그 상태를 완료로 숨기지 않는다.
   - 이미지 편집 도구가 만든 크기·셀 간격·알파를 다시 측정한다. 요청한 그리드가 그대로 나왔다고 가정하여 잘못 자르지 않는다.

4. **정렬과 시트 조립**
   - 전체 프레임에 공통 배율을 적용하고 고정된 지면 기준선 y=448px과 캐릭터 기준점을 사용한다. 프레임마다 바운딩 박스를 꽉 채우거나 개별 확대하여 몸 크기가 출렁이지 않도록 한다.
   - 의도된 걸음의 상하 움직임은 유지한다. 얼굴이나 머리를 매 프레임 같은 높이에 강제하여 동작을 지우지 않는다.
   - 최대 동작 범위와 복원 영역을 함께 고려하여 512×512 셀 안에 최소 32px 여백을 확보한다.
   - 보정과 정렬을 완료한 첫 프레임을 마지막 프레임으로 복제한다. 마지막 칸을 별도로 AI 생성하지 않는다.
   - FFmpeg로 8개 프레임을 `tile=8x1`로 조립하고 RGBA PNG로 출력한다. 루프 미리보기에는 중복 마지막 칸을 제외한다.
   - 재생 속도는 원본 주기 길이 T초에 대해 기본 `fps=7/T`로 맞춘다. 무조건 7 FPS로 고정하지 않는다.

## 검수

- 최종 PNG가 RGBA, 4096×512이고 각 셀이 정확히 512×512인지 확인한다.
- 첫 셀과 마지막 셀의 디코딩된 RGBA 배열을 비교하여 완전히 같은지 확인한다.
- 셀별 alpha>0 영역이 32px 여백을 침범하지 않는지 수치로 확인한다. 위반하면 재배치하거나 전체 프레임의 공통 배율을 조정한다.
- 밝은 배경과 어두운 배경에 합성하여 확인한다. 빈 배경은 alpha=0이고 머리카락 사이·다리 사이도 투명해야 한다. 검은 의상과 칼의 내부가 잘못 투명해지지 않았는지 확인한다.
- 테두리 halo가 남으면 프로젝트의 `image-alpha-bleed` 스킬을 적용하고 알파가 바뀌지 않았는지 검증한다. Alpha bleed는 배경 제거를 대신하지 않는다.
- 접지 프레임에서 발바닥 하단 경계가 y=448px에 맞는지 확대 확인한다. 래스터 경계 판독 오차는 최대 ±1px로 제한하고, 들린 발이나 공중 동작에는 접지 조건을 적용하지 않는다.
- 반복 미리보기로 6→0 전환, 발 위치, 신체 크기, 무기 길이와 잘림, 복원 영역의 깜빡임을 확인한다. 숫자 검증만으로 시각 검수를 대체하지 않는다.

## 저장과 전달

- 사용자가 지정한 결과 경로를 우선한다. 이 프로젝트에서 `images/...`로 지정하면 `assets/images/...` 아래에 저장한다. 목적지가 없으면 기존 캐릭터 폴더 구조를 확인하여 결과 위치를 정한다.
- 기존 파일 교체 요청이 없으면 덮어쓰지 않고 별도 이름을 사용한다. PNG는 프로젝트 규칙에 따라 Git에 강제로 추가하지 않는다.
- 임시 프레임·연락 시트는 이번 작업만의 임시 폴더에 둔다. 최종 시트와 검증이 완료되면 그 폴더만 정리하며 원본 영상과 기존 사용자 파일은 삭제하지 않는다.
- 최종 시트와 반복 미리보기를 제공하고 **1×8 / 프레임 512×512 / 전체 4096×512 / 배경 alpha=0 / 발 기준선 y=448px / 권장 FPS**를 명시한다. 첫·끝 일치 검증, 재생 인덱스 0~6 및 정지 인덱스 7, 추정 복원 여부도 간단히 알린다.
- 이미지 생성 도구를 사용했다면 적용한 스킬의 프롬프트 기록 요구도 따른다. 게임 코드나 저장 형식은 별도 요청 없이 수정하지 않는다.
