# 캐릭터 모션 가공·등록 방법

영상의 게임 등록은 `character_motion_import` 스킬을 사용하고, 영상 가공은 하위 `vedio_to_motion_sheet` 스킬을 따른다. 세부 절차는 해당 스킬의 최신 지침을 확인한다.

1. 영상 전체를 확인해 준비·동작·복귀가 포함된 구간을 선택한다. 반복 동작과 단발 동작을 구분하고 핵심 순간이 빠지지 않게 추출한다.
2. FFmpeg로 프레임을 추출한다. 검은 의상과 배경이 겹치면 단순 검정색 제거를 피하고 이미지 편집으로 배경을 분리한다. 포즈·표정·무기 각도를 보존하고 잘린 부분은 인접 프레임을 참고해 복원한다.
3. 투명 RGBA 시트를 가로 1×8, 프레임 512×512, 전체 4096×512로 조립한다. 0~6은 서로 다른 시점, 7은 보정 완료한 0의 복제다. 전체에 공통 배율을 적용하고 사방 최소 32px 여백과 접지 기준 y=448을 확보한다. 의도된 숙임·점프·전진은 유지한다.
4. `assets/images/characters/{code}/{motion}.png`에 등록한다. 기존 파일명 예외와 공통 모션 목록은 현재 텍스처 매핑에서 확인한다. 요청 없는 기존 파일 덮어쓰기와 PNG의 Git 강제 추가는 하지 않는다.
5. 기존 스탠딩의 머리·몸통 크기와 발 위치에 맞춰 `data/definitions/characters.json`의 해당 `motions`만 조정한다. 배율·anchor·offset을 먼저 맞추고, 생성 과정의 위치 흔들림에만 `frame_offsets`를 사용한다. 개별 보정값은 JSON에서 관리한다.
6. 실제 텍스처 로딩과 단발 재생·대기 복귀·재시작을 확인한다. 스킬이나 전투 이벤트 연결은 리소스 등록과 별개로 처리한다. 원본 FPS를 게임 공통 재생 속도에 자동 반영하지 않는다. 파일 누락 시 현재 렌더러는 스탠딩으로 대체한다.
7. 크기·알파·여백·첫끝 일치·발 위치를 수치로 검사하고, 밝고 어두운 배경과 좌우 반전에서 정렬·잘림·경계를 확인한다. 미리보기의 6→0 전환도 살핀다. JSON은 실제 로더로 검증하고 코드 변경 시 프로젝트 기본 검사를 실행한다.

원본 속도 미리보기는 선택 구간 T초에 대해 7/T FPS로 0~6을 재생한다. 7은 종료 자세이며, 8칸 전체를 반복하면 경계에서 같은 자세가 중복된다. 게임 재시작으로 텍스처 캐시와 정렬 설정을 새로 읽는다.

완료 후 프로젝트에는 최종 PNG, 필요한 설정·코드 변경만 남기고 이번 작업의 임시 프레임·연락 시트는 정리한다. 미리보기는 필요할 때 별도로 제공하며 `output`이나 `tmp`를 영구 기록 저장소로 사용하지 않는다. 원본 영상과 기존 사용자 파일은 보존한다.

`docs`에는 재사용할 방법·규격·책임·동작 흐름만 기록한다. 캐릭터별 가공 일지, 생성 프롬프트 전문, 시행착오, 개별 검증 로그는 누적하지 않는다. 결과 경로·검증 요약·추정 복원 한계는 작업 응답에서 전달한다. 공통 절차나 게임 동작이 바뀔 때만 관련 문서를 갱신한다.
